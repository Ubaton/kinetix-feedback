# Kinetix feedback

Report bugs and suggest improvements for [Kinetix](https://kinetix-app.com/), a workspace for small teams to manage tasks, documents, whiteboards and roadmaps.

**[Try Kinetix](https://kinetix-app.com/)** · **[Report a bug](https://github.com/Ubaton/kinetix-feedback/issues/new?template=bug_report.yml)** · **[Request a feature](https://github.com/Ubaton/kinetix-feedback/issues/new?template=feature_request.yml)**

This is the public feedback tracker. Kinetix's application source is maintained in a separate private repository.

## Before opening an issue

1. [Search existing issues](https://github.com/Ubaton/kinetix-feedback/issues), including closed reports, to check whether the topic is already covered.
2. If you find a match, add useful details or react with a thumbs-up instead of creating a duplicate.
3. Otherwise, choose the bug report or feature request form. A GitHub account is required.

For bugs, include what you did, what you expected, what happened, and your browser and device. Screenshots are helpful when they contain no private information.

For feature requests, explain the problem you want to solve and how it affects your team's work. Requests help guide priorities; submitting one does not guarantee implementation or a delivery date.

## Private support

Issues and comments here are public. Do not post passwords, access tokens, personal information or private workspace content. Remove sensitive information from screenshots and logs before sharing.

For account or access problems, use **Settings > Help** in Kinetix or email [support@kinetix-app.com](mailto:support@kinetix-app.com). You can use these options without a GitHub account.

Report suspected security vulnerabilities privately to [support@kinetix-app.com](mailto:support@kinetix-app.com), rather than opening a public issue.

## Keep feedback useful

Keep one problem or suggestion per issue. Be respectful, describe concrete examples, and reply if more information is needed to reproduce a problem.
